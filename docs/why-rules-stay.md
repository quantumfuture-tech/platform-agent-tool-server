# 为什么规则不交给模型

## 一句话

模型负责听懂人话、决定调哪个工具、把结论说成人话；数字、规则、判定由服务器算。

## 一个具体的失败模式

学生问「我还差多少学分」。如果让模型自己算，它要同时做到：

- 记住 8 门课（真实场景可能是 80 门）各自的学分、所属课程组、通过状态；
- 做跨行求和、分组归类、缺口比例；
- 记住「缺口超过 35% 算高风险」这类口径；
- 每次回答都保持一致，并且能解释上一次是怎么算的。

前三条它可能做对，第四条做不到。提示词修不了算术：把规则写进提示词，只是把「算错」换成了「背错」。

## 服务器算的四个理由

1. **可复现**：同一份规则 + 同一份记录 = 同一份输出。报告编号（reportId）由输入哈希得到，两次调用必然相同。
2. **可审计**：explain 返回 value、rule、inputs 三样东西。任何一条结论都能倒查到「用了哪条规则、吃了哪些输入」。
3. **可测试**：规则是数据，边界值（0.15、0.35）可以写成断言，而不是靠人肉 review 提示词。
4. **可替换**：换模型、换前端、换调用方，结论不变。模型只是五个工具的调用者。

## 模型仍然做什么

- 听懂「我这学期还能不能选课」背后该调哪个工具；
- 决定先看方案（plan）还是先看进度（progress）；
- 把工具返回的 text 转述成人话，信息不足时追问；
- 不编数字：工具没返回的，就说没有。

## 这条边界放在哪

- server/tools.js：只做入参校验与响应形状，不计算；
- engine/index.js：只做计算，不关心 HTTP；
- engine/render.js：把算好的结果渲染成文字，不做二次计算；
- 模型：只拿到 text 与结构化字段。

模型能改的只有「说什么」，改不了「算什么」。
